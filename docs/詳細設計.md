### 機能B

プロンプト例

[1]
```text
住民からの『騒音やポイ捨て、立ち入り禁止の私有地への侵入』などの苦情を、内容を追加せず丁寧な文章に整え、日本語・英語の追加候補をJSON形式で出力してください。公開の採否は決定しないでください。
```

[2]
```text
地域の公開情報に矛盾する内容や、更新確認が必要な古い情報があれば、管理者の確認候補をJSON形式で出力してください。公開情報は変更しないでください。
```

### 機能C
観光客のドキュメントの閲覧機能
- 地図上の特定ピンを押すとドキュメント画面へ遷移
- テキストバーで地域を検索してドキュメント画面へ遷移。地域の一覧は `GET /api/regions` で取得し、地域名での検索はフロントで行う
- JSON形式の公開データをWebページに表示

### 機能D
- 管理者が候補の採用・不採用を決める
- 採用した候補をFastAPI経由でFirestoreへ反映する
- 管理者は公開ドキュメントを手動で編集できる
- 管理者のログイン機能（Firebase Authentication）

## DB
Firestore

管理者テーブル構成

Firebase UID(index) | 社員名

コレクション構成

| コレクション | スキーマ | ドキュメントID |
| --- | --- | --- |
| `admins` | `Admin` | Firebase UID |
| `posts` | `StoredPost` | 自動ID |
| `candidates` | `Candidate` | `{post_id}_{連番}` |
| `rules` | `Rule` | 自動ID |
| `regions` | `Region` | `Region.id`(例：`sakai`) |
| `locks` | `run_id`・`locked_until` | `candidate_batch` |

- `StoredPost`：`Post` に `status`(`unprocessed` / `processing` / `processed`)・`status_updated_at`・`created_at` を足したもの。日時は UTC で保存する
- `Candidate.post_id`：元の `Post` のID
- 詳しい方針は [#12](https://github.com/Devfest-Hackathon-2026-team-180/hack26-app/issues/12) を参照

## API設計
POST /api/posts：住民の投稿
GET /api/regions：対応地域の一覧取得
GET /api/regions/{id}/rules：地域の公開ルール取得
GET /api/admin/candidates：管理者の候補一覧取得
PATCH /api/admin/candidates/{id}：候補の採用・却下
PATCH /api/admin/rules/{id}：公開ルールの編集

## 認証・権限設計
認証：Firebase Authentication
住民：情報の投稿
観光客：公開ルールの閲覧
管理者：候補の採否判断・公開ルールの編集

FastAPIでFirebase IDトークンと管理者権限を検証する。

## 投稿仕様
text：必須
region：必須
reason：任意

## AIの処理・JSON Schema
Geminiが投稿を整形し、日本語・英語の候補を生成する。
矛盾・古い情報は確認候補として抽出する。
採用・削除は管理者が判断する。

## データ更新・履歴管理
管理者が採用した情報のみ公開データに反映する。
公開ルールは項目単位で追加・更新する。
更新日時を記録する。

## 地図・位置情報の仕様
Google Maps JavaScript APIを使用。(Google Earth API使えるって思ってたけど提供終了してた)
初期対応地域：大阪府堺市
地域検索・地図上のピンからルールを閲覧する。

## 技術スタック
フレームワーク: React, FastAPI
LLM: Gemini
DB: Firestore
認証: Firebase Authentication
使用API: Agent Platform 経由の Gemini, Google Maps JavaScript API
実行基盤: Firebase Hosting, Cloud Run

## フロー
住民の入力 → Geminiが候補を整形・翻訳 → 管理者が採否を判断 → FastAPI経由でFirestoreを更新 → 観光客が検索・閲覧
